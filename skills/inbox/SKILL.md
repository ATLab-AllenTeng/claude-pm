# 收件匣

使用者不一定一直盯著每個對話。要他決定的事集中放在收件匣網頁，他有空時一次看完、一次回答。他回答之後，答案會在你下一輪自動出現在上下文裡，開頭是「收件匣：使用者回覆了 N 則」。

## 什麼時候出題

- 要他做決定、而且你猜錯的代價比等他回答高：方向選擇、不可逆的動作、改到別人看得到的行為。
- 要他知道一件事，但不需要他決定：用 `--info`，他按「我知道了」就好。
- 你自己能從程式、測試或文件查到答案的事，不要出題。

## 怎麼出題

```bash
inbox ask --title "登入頁要不要保留舊的帳密登入？" \
  --body "新版改成只用 Google 登入。目前還有 3 個帳號只用帳密登入。" \
  --option "A=保留帳密登入，兩種並存" \
  --option "B=只留 Google，通知那 3 個人改用 Google" \
  --recommend A \
  --deadline "今天 18:00 前"
```

- `--title` 寫成一個問句，不看內文也懂要決定什麼。
- `--body` 給剛好夠決定的背景，兩三句就好；長內容用 `--body-file`。支援空行分段、`**粗體**`、`` `程式碼` `` 和網址。
- 每個選項寫「動作和它的後果」。推薦的放第一個並用 `--recommend` 標出來。
- 沒有選項的題目也可以出，使用者會直接寫答案。
- 只是知會：`inbox ask --info --title "..." --body "..."`。

出題後指令會印出題號和網址。第一次出題時會自動在背景起網頁服務。

**每次出題或放摘要，回覆裡都要附上完整網址。** 把指令印出的那行網址原樣貼給使用者，含 `?t=` 後面的 token，讓他點了就能開。印出「外部」和「本機」兩個網址時，給「外部」那個，他多半不在這台機器前面。不要只說「已放進收件匣」而不給連結，也不要等他問。指令沒印出網址（例如服務沒起來）時，跑 `inbox url` 拿；拿不到就照實說，附上 `server.log` 的位置。

如果 `inbox` 指令找不到，改用 `python3 "${CLAUDE_PLUGIN_ROOT}/inbox/inbox.py"`（Windows 上 `python3` 不能執行時改用 `python`），後面參數一樣。

## 使用者直接叫你看收件匣時

使用者輸入 `/inbox:inbox`、或說「打開收件匣」「收件匣連結給我」，卻沒有交代要出什麼題時，他要的是那個網頁。依序做：

1. 跑 `inbox url`，把網址照上面的規則貼給他。
2. 跑 `inbox list`，用一句話說現在有幾題在等他回答、幾則摘要還沒讀；都沒有就說沒有。
3. 跑 `inbox take`，有新回覆就照回覆處理。

不要只讀完這份說明就停下來。

## 做完要讓使用者知道結果時

一件事做完，想讓使用者知道結果、但不需要他決定什麼，用完成摘要：

```bash
inbox report --title "登入頁改版：完成，已合進 main" --body "保留了帳密登入。測試都過。"
```

摘要在收件匣裡自成一區，使用者讀完按刪除就不見了，你不用 `inbox close`。他如果寫了意見，會像回覆一樣出現在你的上下文，開頭是「完成摘要：」。需要他決定的事不要放在摘要裡，照樣用 `inbox ask`。

## 專案已有自己的規則時

收件匣只是「問使用者」的管道，不改變該問什麼、誰能決定。

- 專案的 `CLAUDE.md`、`AGENTS.md` 或其他規則寫了哪些事要先問使用者，照樣問；只是問的地方改成收件匣，不要在對話裡停下來等。
- 規則寫了哪些事你可以自己決定，照樣自己決定，不要因為有收件匣就多問。
- 規則和這份說明衝突時，聽專案的規則。

## 出完題之後

- 不要在對話裡停下來等。先做不受這題影響的工作。
- 一定得等答案才能往下時，用 Bash 的背景執行跑 `inbox wait --timeout 1800`。有回覆時它會印出答案並結束，你就會被叫醒。
- 想手動看有沒有新回覆：`inbox take`。
- 答案照使用者選的做。他的補充說明比選項文字優先。
- 處理完一題後跑 `inbox close <題號>`，把它從使用者的畫面收起來。

## 答案會送到哪個對話

答案只送回出題的那個對話；它只是閒置、還開著的話，放多久都留給它。出題的對話結束後（關掉、`/clear`、切到別的對話），同一個專案裡的其他對話下一輪就會拿到，所以出題的對話結束了也不會掉。對話沒正常結束就消失（例如當機）時，24 小時沒動靜後同專案的其他對話才接手。每則答案成功交出後就不再送。
